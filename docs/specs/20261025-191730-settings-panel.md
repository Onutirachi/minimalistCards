# Painel de configurações

- **Criada em:** 2026-10-25 19:17:30
- **Status:** Implemented
- **Código:** `tools/settingsPanel.mjs`, `tools/projectJson.mjs`, `project.json`, `tests/settingsPanel.test.js`

## Contexto

O painel de propriedades do Wallpaper Engine é a única interface de configuração do wallpaper. Ele era difícil de usar:

- uma lista longa de nomes técnicos com prefixo repetido ("Audio Bars - Peak Dots Border Radius");
- nenhuma explicação do que cada opção faz;
- opções de recursos desligados continuavam visíveis.

O WE renderiza HTML nos rótulos (títulos, `<small>`, `<br>`, `<b>`, emoji), inclusive nos rótulos de sliders e grupos. Isso foi verificado no WE. Uma imagem local (`<img src="preview.gif">`) não carregou, então o painel não usa imagens. Com isso, o painel pode ter seções e explicações sem nenhum código no wallpaper.

O wallpaper não consegue gravar propriedades do WE. Um menu dentro do próprio wallpaper fica fora desta spec.

## Requisitos

- **REQ-UI-1** — As chaves e os valores das opções existentes NÃO DEVEM mudar, para nenhum usuário perder configurações salvas. Só rótulo, ordem e condição podem mudar.
- **REQ-UI-2** — Cada seção DEVE ter um título com emoji e uma frase curta, em inglês simples, dizendo o que ela controla.
- **REQ-UI-3** — Os rótulos das opções DEVEM ser curtos e sem o prefixo da seção. Toda opção DEVE ter, logo abaixo, uma dica curta em texto menor, na largura total do painel, terminando com o valor padrão (`Default value = …`), seguida de uma linha separadora antes da próxima opção.
- **REQ-UI-4** — QUANDO um recurso estiver desligado (card, barras, peak dots, Album Spin, triângulos), as opções dele DEVEM ficar ocultas.
- **REQ-UI-5** — Opções avançadas DEVEM vir depois das comuns, explicadas na própria dica, sem subtítulo à parte.
- **REQ-UI-6** — Propriedades só de rótulo (tipo `text`) NÃO DEVEM exigir código. Elas são ignoradas pelo `settings.js` e pelos testes.

## Design

- **Geração:** o painel é definido em `tools/settingsPanel.mjs` e aplicado ao `project.json` com `npm run panel`, que grava no formato do WE (`tools/projectJson.mjs`). O script só escreve rótulo, ordem, condição e rótulos de combo, e falha se alguma opção do `project.json` não estiver no painel.
- **Estrutura de cada seção:** um `group` com o título (emoji + nome), seguido de uma propriedade `text` com a descrição em `<small>` e, depois, as opções.
- **Topo do painel:** o nome, uma frase de apresentação e a dica de Reset, cada um seguido de uma linha em branco (a propriedade `information` existente, só com o texto novo). Não há banner: o WE já mostra o `preview.gif` acima do painel.
- **Seções:** Layout, Clock, Now Playing, Audio Bars, Date, Background, Album Spin, Triangles. Background tem só a camada de baixo (cor sólida) e a de cima (imagem do usuário), mais o Beat pulse, que vale para a imagem e para a capa. A capa girando ganhou o nome **Album Spin** e uma seção própria, como os triângulos.
- **Dicas:** o rótulo de uma opção fica numa coluna ao lado do controle, então a dica é uma propriedade `text` separada, `hint<chave>` (por exemplo `hintcardssize`), logo depois da opção, com a mesma condição dela: `<small>dica</small><hr width="260">`. O `<hr>` separa uma opção da outra.
- **Valor padrão na dica:** vem do `value` da opção no `project.json`, no momento em que o painel é gerado. Checkbox aparece como On/Off, combo pelo rótulo da opção, cor pelo nome (ou hex) e arquivo vazio como "none". A última opção de cada seção não tem separador, porque o título da próxima seção já separa.
- **Largura do separador:** no WE, um rótulo encolhe até a largura do texto, e um `<hr>` comum (ou com `width="100%"`, ou dentro de uma tabela de 100%) fica do tamanho da dica. Testado no WE: só a largura fixa em pixels atravessa o painel. Uma borda via CSS não aparece, e caracteres `─` quebram linha. Uma linha invisível comprida também força a largura total, mas cria um espaço grande.
- **Rótulos de combo:** as fontes de cor passam a ser "My color" e "Album: main color", entre outras. Os valores (`custom`, `primary`…) não mudam.
- **Ordem:** o WE ordena as propriedades pelo `index`, não pelo `order`. Os dois são gravados iguais.
- **Chaves novas:** só para rótulos: `label…` para descrições de seção, `hint…` para dicas de opção e os `group` novos `cards` (Layout) e `albumspin` (Album Spin). As opções da capa continuam com as chaves `background…`.
